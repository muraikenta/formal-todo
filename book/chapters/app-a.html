付録A Lean の基本文法

本編のコード抜粋を読むときに引く早見です。網羅はせず、本書に出てくるものだけを TypeScript と並べて載せます。例はすべて Lean 4.36 で検査を通しています。

この付録のゴール

  • 本編の def・structure・theorem を、TypeScript に置き換えて読める
  • 主張の記号（∧・∀・∈ など）を声に出して読める
  • 証明の中の decide・simp・rw などが「何をしてくれるか」が分かる

(e : T)e as T式に型を書き添える。TypeScript と違い、合わなければエラーになる
deriving DecidableEq, Reprなし「等しいかを計算で判定できる」「#eval で表示できる」を自動で付ける
Propなし真偽値ではなく主張。証明するもの。真偽を計算で決める手順がある主張だけは decide で確かめられる

Sorted・IsSortOf・Inv（第0章・第1章）は Prop を返す関数です。「この形の主張」を名前で呼べるようにしています。第0章の Sorted・IsSortOf に by decide が効くのも、Spec.lean に上と同じ instance の行があるからです。

落とし穴def で名前を付けた Prop に by decide を使うと、instance の行が無ければ failed to synthesize Decidable … で止まります。主張が間違っているのではなく、計算の仕方が分からないというエラーです。

定理と証明

形は theorem 名前 (前提 : 主張) : 示したい主張 := by 手順 です。前提は関数の引数と同じ書き方で、「この前提が手に入ったら」と読みます。名前の要らない定理は example で書きます。by の後に並ぶ1つ1つの命令をタクティクと呼びます。

書き方何をしてくれるか
by decide具体的な値の主張を、計算して確かめる（テストに近い）。変数を含む主張や、無限にある値についての ∀ には使えない
simp [f, h, 定理]標準の書き換え規則に、渡した定義・前提・定理を足して目標を簡単にする。閉じきれなければ残った形が次の目標になる
unfold f関数 f を定義の中身に展開する
rw [h]等式 h : a = b で、目標の a を b に書き換える
exact e「これがそのまま証明です」と e を渡す
apply f「f を使えば示せる」とし、f の前提で足りない分を次の目標にする
rintro ⟨a, b⟩∀ や → の前提を受け取り、組や ∧ を分解して名前を付ける。- は使わない側を捨てる
split目標の中の if や match を、枝ごとの目標に分ける
show P今の目標をこの形で見る、と書いて読みやすくする
_引数や式の一部を Lean に推論して埋めてもらう
手順1; 手順2手順を1行に並べる（改行と同じ）
sorry証明を後回しにする。検査は警告を出し、証明済みとは扱わない
#eval e・#check e式を計算して表示する／式の型を表示する（この付録の例で使う）
落とし穴sorry が1つでも残ると、その定理は証明されていません。本書の検査で「sorry なし」と数えているのはこのためです。

第1章の翻訳結果では、Result・ok・←・1#u32 がまとめて出てきます。

t.next_id + 1#u32 もあふれうる計算なので ← で受けます。⦃ ⦄ は、この関数の結果について主張するときに使います。

r t' は返り値の組 (返り値, 新しい状態) を2つの名前で受けています。r.map (·.val) は Option U32 の中身を Nat に直してから仕様と比べています。

第2章の toggle_others_rust も、上の表のタクティクで読めます。

  • apply WP.spec_mono (…): 証明済みの toggle_correct の結論から、今の結論が出ることを示せばよい、とする
  • rintro ⟨b, t'⟩ ⟨-, h⟩: 返り値の組を b・t' に分け、toggle_correct の結論（∧）の前半を捨て、後半 abs t' = … を h と呼ぶ
  • rw [h]; exact …: abs t' を仕様の toggle の結果に書き換え、仕様の定理 Spec.toggle_others で閉じる。_ _ _ _ の引数は Lean が埋め、.mp で user ≠ other を user.val ≠ other.val に直して渡す

まとめ

  • 関数の適用は空白、型は 名前 : 型。· は短い無名関数、xs.map f は List.map f xs
  • ==・&& は Bool の計算、=・∧・∀ は Prop の主張。decide が効くのは計算で決められる主張だけ
  • 定理は「前提を引数に取り、主張を型に書き、by の後に手順を書く」。sorry が残れば未証明
  • Aeneas の翻訳結果は Result を返し、⦃ ⦄ で「panic も無限ループもせず、結果がこれを満たす」と書く
